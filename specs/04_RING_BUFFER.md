# 04. Кольцевой буфер и управление памятью (Ring Buffer)

## 1. Концепция
Кольцевой буфер OmniClip хранит **уже сжатые пакеты** (видео и аудио) в системной RAM.

### Расчёт памяти:
- Длительность повтора: 60 секунд.
- Битрейт видео: 30 Мбит/с = 3.75 МБ/с $\rightarrow$ ~225 МБ.
- Битрейт аудио: 256 кбит/с = 32 КБ/с $\rightarrow$ ~1.9 МБ.
- Итоговый расход RAM: **~230–250 МБ** (для 120 секунд: ~460–500 МБ).

## 2. Структуры данных

```rust
use std::collections::VecDeque;

#[derive(Clone, Debug)]
pub struct VideoChunk {
    pub is_keyframe: bool,   // IDR кадр (наличие SPS/PPS)
    pub pts_hns: i64,        // Презентационный таймстемп в 100-нс единицах
    pub dts_hns: i64,        // Декодировочный таймстемп
    pub duration_hns: i64,   // Длительность кадра
    pub data: Vec<u8>,       // NAL-юниты
}

#[derive(Clone, Debug)]
pub struct AudioChunk {
    pub pts_hns: i64,
    pub duration_hns: i64,
    pub data: Vec<u8>,       // AAC-фреймы
}

pub struct RingBuffer {
    max_duration_hns: i64,
    video_chunks: VecDeque<VideoChunk>,
    audio_chunks: VecDeque<AudioChunk>,
    keyframe_indices: VecDeque<usize>, // Глобальные индексы IDR кадров
    total_bytes: usize,
}
```

## 3. Алгоритм выравнивания по ключевым кадрам (IDR-Pruning)

Видеопоток H.264/HEVC не может быть декодирован с произвольного P- или B-кадра. Начало видеофайла обязано содержать IDR-кадр с конфигурационными заголовками SPS (Sequence Parameter Set) и PPS (Picture Parameter Set).

### Правило очистки буфера:
1. При добавлении нового видеопакета обновляется максимальный `latest_pts`.
2. Рассчитывается текущая протяженность: $\Delta = \text{latest\_pts} - \text{first\_pts}$.
3. Если $\Delta > \text{max\_duration\_hns}$:
   - Находится ближайший следующий ключевой кадр (`is_keyframe == true`).
   - Удаляются все пакеты, предшествующие этому ключевому кадру.
   - Соответствующим образом отсекаются устаревшие аудиопакеты (`audio.pts < new_first_video.pts`).

```
[Старые кадры (P, B)] -> [IDR 1] -> [P, B, P] -> [IDR 2] ... -> [Новейший кадр]
 ^^^^^^^^^^^^^^^^^^^^^^^^^
 Удаляются целиком до IDR 1, чтобы буфер всегда начинался с валидного IDR!
```

## 4. Снятие слепка (Snapshot) для сохранения
Когда поступает сигнал `DumpReplay`:
1. Кольцевой буфер блокируется на время клонирования структуры метаданных и указателей (или перемещения ссылок в `Arc<Vec<u8>>`).
2. Время блокировки: **< 1 миллисекунды**.
3. Снимок передаётся в фоновый поток сброса на диск (`DiskWriter`).
4. Основной поток продолжает принимать новые кадры без пауз и задержек.
